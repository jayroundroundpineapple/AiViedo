# 01 · 数据规范

> 数据不规范的代价是：三个月后你有一堆数字，但回答不了「哪种钩子在我的赛道有效」。
> 这份文档定义**字段、命名、提交**三件事。

---

## 一、主键与命名规则

### video_id

```
YYYYMMDD-平台-序号
20261109-dy-01
```

- **平台代码**：`dy` 抖音 / `xhs` 小红书 / `bl` B站 / `sph` 视频号 / `yt` YouTube / `tt` TikTok
- **序号**：当天该平台第几条，两位数，从 `01` 开始
- **唯一性**：一旦生成不再修改，成片文件名也用这个 id

### track_id（赛道代码）

```
T01, T02, ... T99
```

赛道定义写在 `data/tracks.csv`，代码一旦分配不复用。已放弃的赛道保留记录、标记状态，**不要删除**——放弃的原因本身就是重要信息。

---

## 二、`data/videos.csv` 字段定义

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `video_id` | str | ✅ | 主键，见上 |
| `publish_date` | date | ✅ | `YYYY-MM-DD` |
| `platform` | enum | ✅ | 见平台代码 |
| `track` | str | ✅ | 赛道代码 |
| `title` | str | ✅ | 发布时的完整标题（含话题标签） |
| `form` | enum | ✅ | `ai_full` 全AI / `digital_human` 数字人 / `ai_assisted` AI素材+人工精剪 |
| `hook_type` | enum | ✅ | `反常识` / `结果前置` / `冲突` / `痛点` / `悬念` / `对比` |
| `duration_sec` | int | ✅ | 成片时长（秒） |
| `shots` | int | ✅ | 镜头数量 |
| `cost_min` | int | ✅ | 从选题到成片的总人工耗时（分钟），用于算毛利 |
| `views_72h` | int | ✅ | 发布后 72 小时播放量 |
| `rate_3s` | float | ✅ | 3 秒完播率，0-1 之间，如 `0.42` |
| `rate_complete` | float | ✅ | 完播率，0-1 之间 |
| `likes` | int | ✅ | 点赞 |
| `comments` | int | ✅ | 评论 |
| `shares` | int | ✅ | 转发 |
| `saves` | int | ✅ | 收藏（小红书尤其重要） |
| `follows` | int | ✅ | 带来涨粉数 |
| `gmv` | float | ⬜ | 直接成交额，无则填 `0` |
| `notes` | str | ✅ | **一句话结论**，不是描述。写「钩子有效，中段掉量」而不是「发了条视频」 |

### 空值规则

- 数字字段没有数据填 `0`，**不许留空**
- 无法获取的指标填 `NA`（字符串），统计脚本会自动跳过
- 空字符串会导致统计静默算错，比填错更难排查

## 三、`data/metrics.csv` 字段定义

同一条视频在不同时点多次记录，用于画增长曲线、判断流量是否还有长尾。

| 字段 | 说明 |
|---|---|
| `video_id` | 关联主表 |
| `snapshot_at` | 快照时间 `YYYY-MM-DD HH:MM` |
| `views` | 累计播放 |
| `likes` / `comments` / `shares` / `saves` / `follows` | 累计互动 |

**建议快照节奏**：发布后 1h / 6h / 24h / 72h / 7d。前三个点能看出算法是否给了二次推荐。

## 四、`data/tracks.csv` 字段定义

| 字段 | 说明 |
|---|---|
| `track_id` | `T01` |
| `name` | 赛道名，如「跨境电商母婴用品」 |
| `platform` | 主要平台 |
| `status` | `candidate` 候选 / `active` 在跑 / `paused` 暂停 / `dropped` 放弃 |
| `score_need` | 需求热度 0-10 |
| `score_comp` | 竞争强度 0-10（**越高越差**） |
| `score_money` | 变现距离 0-10（离钱多近） |
| `score_durable` | 可持续性 0-10（能不能做 100 条） |
| `score_fit` | 资源匹配 0-10（你的优势） |
| `score_risk` | 合规风险 0-10（**越高越差**） |
| `total` | 加权总分，由脚本计算 |
| `verdict` | `立项` / `观察` / `放弃` |
| `reason` | 一句话判断依据 |

打分方法见 `docs/03-赛道评估模型.md`。

## 五、提交规则（重要）

### 必须提交

- 所有 `.csv` 台账（这是仓库的核心资产）
- `docs/`、`prompts/`、`templates/` 的文档变更
- `scripts/` 的代码变更
- 有价值的对话结论 → 整理进 `docs/` 或 `prompts/`，**不要存原始聊天记录**

### 禁止提交

| 类型 | 原因 |
|---|---|
| cookie / token / `.env` | 账号安全 |
| 抓取到的用户昵称、头像、主页链接 | 个人信息，法律风险 |
| 成片、素材、音频文件 | 体积大，放网盘 |
| 平台原始导出（`data/raw/`） | 体积大，且可能含个人信息 |
| 客户名称、合同金额、真实报价单 | 商业敏感 |

### 提交信息格式

```
<类型>: <一句话说明>

类型：feat 新增 / data 数据 / docs 文档 / fix 修复 / chore 杂务
```

示例：

```
data: 登记 11/09 抖音 3 条，补 72h 快照
docs: 补充赛道评估的合规风险维度
feat: new_video.py 支持批量导入
```
